# AGENTS.md — Rechnungsarchiv

Local, tamper-evident invoice archive for Austrian SMEs. A folder of invoices becomes a read-only BagIt ZIP (an "Ablage"). Only its 32-byte hash, the "Prüfwert" (plus the login at the TSA, i.e. account name and password or client certificate, and the IP address inherent to the request), goes to one qualified EU timestamp provider (RFC 3161; see ADR-0001). Invoices, file names and per-file hashes never leave the machine.

## Setup runbook

For agents asked to "set up Rechnungsarchiv" for a user. Ask the user only for: company name, archive folder, timestamp provider (recommend `mensatek`, see the README provider table) and the provider username. **Never put a password or key on a command line or in chat output.**

1. **Install the signed release** (`$APP` below). Ask before installing; it adds Start menu and desktop entries, no admin rights:
   ```powershell
   $ErrorActionPreference = 'Stop'
   $setup = Join-Path $env:TEMP 'Rechnungsarchiv-win-Setup.exe'
   Invoke-WebRequest 'https://github.com/realspqrk/rechnungsarchiv/releases/latest/download/Rechnungsarchiv-win-Setup.exe' -OutFile $setup
   $sig = Get-AuthenticodeSignature $setup
   if ($sig.Status -ne 'Valid' -or $sig.SignerCertificate.Subject -ne 'CN=Gerhard Petermeir, O=Gerhard Petermeir, L=Bad Gleichenberg, S=Steiermark, C=AT') { throw "Signatur ungültig: $($sig.Status) $($sig.SignerCertificate.Subject)" }
   $p = Start-Process $setup -ArgumentList '--silent' -Wait -PassThru
   if ($p.ExitCode -ne 0) { throw "Setup fehlgeschlagen ($($p.ExitCode))" }
   $APP = "$env:LOCALAPPDATA\Rechnungsarchiv\current\rechnungsarchiv.exe"
   & $APP --version                                    # {"version":"x.y.z"}
   ```
   From source instead, in a clone: `cd app; wails3 build; cd ..` (needs Node + wails3 v3.1.0, see app/README.md), then `$APP = (Resolve-Path '.\bin\rechnungsarchiv.exe').Path`. `$APP` is CLI and window in one file; `rechnungsarchiv-gui.exe` next to it is the window launcher for shortcuts. In PowerShell always call it as `& $APP …`. Read `& $APP --help` (the manual) and, before first use of any command, `& $APP <command> --help`.
2. `& $APP status --json`:
   - exit 3 with `NO_ARCHIVE` → step 3;
   - exit 0 → the archive exists; check `provider` and `credentials`.
3. `& $APP init "<Archivordner>" --firma "<Firma>" --json`. This is remembered as the default archive.
4. Provider + credentials: the user runs this **in their own terminal**; the password prompt is hidden:
   ```powershell
   & $APP provider set mensatek --user <USER>
   ```
   - Only if the user explicitly hands you the secret: pipe it on stdin, never as an argument.
   - PowerShell 5.1 pipes ASCII, so umlauts break; prefer the interactive prompt.
   - Check with `& $APP provider show --json`: `credentials.stored: true`, no secret is printed.
5. Dry run on a folder of the user's invoices: `& $APP archive --dry-run "<Ordner>" --json`.
   - Expected: exit 0, `count` = the files that will be archived (system files such as `Thumbs.db` are listed in `skipped` and not counted), nothing written.
   - In a clone of the repository, the demo invoices work too: `& $APP archive --dry-run "testdata\demo\2026-10 Eingangsrechnungen" --json` → `count` 9, `skipped` `["Thumbs.db"]`.
   - A real `archive … --yes` commits an Ablage and **buys one timestamp**. Run it only after the user agreed to exactly that.
   - Then run `& $APP verify --json` (exit 0 = Zeitgestempelt; exit 6 = pending, check `reason`).
6. Tell the user:
   - Window: `rechnungsarchiv-gui.exe`, or `& $APP gui`.
   - CLI: `archive --dry-run <ordner>`, then `archive <ordner>`, then `verify`, and `export --von <jahr> --bis <jahr> <ziel>` for a tax audit.
   - Back up the archive folder after each timestamp.

## Layout
- `cmd/rechnungsarchiv/`: the one app binary `rechnungsarchiv.exe` (ADR-0008): the CLI, and with `gui` (or no arguments from Explorer) the window. It is also the standalone verifier shipped in auditor exports.
- `cmd/rechnungsarchiv-gui/`: Windows-subsystem launcher for shortcuts; only starts `rechnungsarchiv.exe gui …`. No logic, no Wails.
- `internal/`: the core. Packages: `bag`, `archive`, `tsa`, `trust`, `verify`, `export`, `report`.
- `app/`: the Wails v3 GUI as library package `app` (`app.Run`), a thin shell. No business logic lives here.
- `testdata/`: demo invoices, generated by `go run ./internal/tools/demodata`.

## Rules
- **One implementation per function.** The CLI and GUI render `verify.Report` and call the same core functions. Never duplicate logic in `app/`.
- **Never convert originals.** Store them byte-identical: no PDF/A, no re-encoding.
- **The verifier is security-critical.** Every proof-verification change needs these tests: cert injection, tampered attributes, replay, malformed input. Missing validation material = `Unbestimmt` (indeterminate), never green.
- **Append-only evidence.** Write to a temp file, then fsync and rename. Never rewrite an Ablage ZIP after commit.
- **Only the Prüfwert (plus the TSA login and the IP address, inherent to the request) leaves the machine.** The login is sent to the provider, stored only in this PC's credential store. Never send file names, per-file hashes, invoice bytes or sidecars.
- **Language.**
  - English: code, comments, identifiers, commit messages, `docs/spec.md`, `docs/adr/`, `docs/dev/`, `docs/cli.md`, `docs/agents/`.
  - German: UI text, CLI output, `README.md` and user docs in `docs/*.md`.
  - UI terms: Archiv, Ablage, Zeitstempel, Prüfwert (details only). Actions: "Ordner archivieren", "Archiv kontrollieren", "Export für Betriebsprüfung". Never "Siegel" (collides with the eIDAS seal), never "Bestätigt" (reads as tax-office approval).
- **Claims.** Never call the tool "BMF-genehmigt" (BMF-approved) or "zertifiziert" (certified). It proves *unchanged since at the latest T*, not that the invoice is authentic or that the archive is complete.
- **No prices in code or UI.** Prices live only in the README, with a date.
- **Disclaimer.** `docs/haftungsausschluss.md` is the only source; the app embeds it (`go:embed`) and the README links it. The Archivprotokoll PDF contains **no** disclaimer: it is a factual statement only.
- **YAGNI.** Prefer stdlib. New dependencies need a reason in the PR.
- **Tests.** End-to-end over the demo invoices beats granular unit tests. Delete tests that only lock in implementation details.
