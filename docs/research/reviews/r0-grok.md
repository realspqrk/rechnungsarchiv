VERDICT: accept-with-changes

The local bag, the predecessor hash, and stamping one root are sound. The stamps prove less than the draft assumes, and several controls fail against the holder of the files.

1. Truncation stays possible. A chain proves a prefix only while the head is fixed. Deleting the newest packages and sidecars leaves a shorter chain that still verifies. Object Lock is off by default, ends with the account, and an auditor sees it only if the company opens the account. Bitcoin cannot carry completeness: a public line "this firm, this head" contradicts EDPB 02/2025 para 52, which is why the nonce exists.
Fix: TSA and OTS stay unlinkable existence proofs. Completeness is a named second holder. After every successful stamp, append one line (sequence, seal, TSA time) to a Siegelliste and send it to the Steuerberater. `verify` reports a missing tail against that list. Cut S3 and minio-go from v1.

2. Offline seal plus "retry on next start" leaves many folders without a proof. Until a token is stored, a read-only bit does not bind the owner: the file can be swapped and the clock rolled back. A pending `.ots` is a calendar promise and must not count as a Nachweis. Bitcoin time arrives hours later, outside the TSA skew window. Bookkeepers will not reopen the app that evening.
Fix: stay yellow until one qualified token verifies, or two free tokens lie within one hour. Upgraded OTS is required before green when there is no qualified token. genTime more than an hour before the predecessor is a failure. A token that is present but invalid fails the package, so a disagreeing TSA cannot be dropped. Install a scheduled task for OTS upgrade.

3. Verification as written will both falsely pass and rot. The OS root pool trusts every local CA, including a private timeStamping CA, and it drops roots over a decade so old tokens die. The CVE-2026-39984 test is mandatory: an extra certificate in the bag is not the signer. Check ESSCertID and ESSCertIDv2 with the algorithm the token states. "Qualified" is an allowlisted policy plus a pinned QTSP chain, not the URL the user typed. `sha256(siegel ‖ sha256(token) …)` is still SHA-256, is not RFC 4998, and `openssl` cannot check it. One header and a proof-of-work check is not a Bitcoin proof.
Fix: ship a versioned TSA root file, store its hash in the Nachweis, and verify evidence only against it. The OS pool is for TLS to the TSA. Compare the TSA nonce as an integer to the stored request nonce. Use a fresh nonce; the Seal-Nonce stays in the bag. Renewal is a new RFC 3161 token over the previous `.tsr` (`openssl ts -verify -data old.tsr`). Once a year, while SHA-256 still holds, timestamp the SHA-512 root as its own imprint. Vendor `nbd-wtf/opentimestamps` v0.4.0 for submit, upgrade, and the merkle path. Its verify calls Esplora or bitcoind: pass the stored header and separately require mainnet difficulty for that height. Do not write a second calendar client.

4. The sidecar and the tombstone are editable files. Rewritten JSON is not append-only. Dropping one token hides a contradiction. A tombstone can hide a deletion. If the nonce is copied into the Nachweis, deleting the ZIP does not unlink the public hash. Two PCs sealing the same predecessor on a shared folder fork the chain.
Fix: write raw `NNNN.tsr`, `.ots`, and `.pem` beside the zip. JSON only names those files. Append renewals. The nonce lives only in the bag. Deletion writes a timestamped Löschvermerk; `verify` says VORZEITIG GELÖSCHT if the token time is before Aufbewahrung-Bis. A second genesis, or two packages with the same Previous-Seal, is a hard error. Read the sequence from bag-info, not the filename. Pin bag-info and the tagmanifest to UTF-8, LF, no folding, two-space `sha256sum` lines, and a fixed label order. Record skipped names inside the bag.

5. Retention uses the wrong year, and day-one import looks like ongoing capture. "Seal year + 7" over-keeps personal data (GDPR Art. 5(1)(e)) and misses the 10-year §207 practice and the 10-year OSS case. Auditors read the Verfahrensdokumentation (UStR Rz 1564g, KFS/DV 1); a blank template stays blank. "Unverändert seit …" will be read as "this invoice is true".
Fix: require Belegjahr, default retention 10 years, Grundstück 22 opt-in. Mark day-one seals as Erstübernahme. Generate the Verfahrensdokumentation from the real config: anchors, retention, Windows user in bag-info, backup, second holder. The verdict is "bytes unchanged since T". §11 remains the booking control in the accounting system.

6. Cut from v1: S3, the custom renewal concatenation, anchor dashboards, and deterministic ZIP as a user promise. Keep one developer fixture and use `CreateRaw`, or the 0x5455 extra field changes the bytes. Keep the qualified TSA: Art. 41(2) is the only presumption, so it is the recommended path (~€20/year), with the PKCS#12 in Windows Credential Manager. Ship a static `pruefen` binary on a Prüfer-USB with the raw tokens and a one-page sheet. Add aliases `sichern` and `pruefen`.

7. GUI and words. Wails v3, exact tag, Go 1.26. v3 does not build on Go 1.25; v2 gets critical fixes only; do not float weekly v3 minors. The window calls Seal and Verify and is outside the auditor path. Do not show Paket or Siegel (Siegel already means an eIDAS seal). One action: "Ordner sichern". Status: gesichert / Zeitstempel fehlt / gültig bis. Call the hash Prüfwert.
